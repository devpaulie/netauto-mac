# netauto

**한국어** · [English](README.en.md)

*by devpaulie*

**Wi-Fi에 따라 네트워크 설정을 자동으로 바꿔주는 맥 메뉴바 앱.**

사무실 Wi-Fi(`OfficeWiFi`)에 붙으면 사내 설정(고정 IP + 프록시)으로,
집이나 카페에 붙으면 일반 설정(DHCP)으로 — 손 안 대고 알아서.

```
메뉴바:   📶 Auto        ← 지금 일반 설정
          🏢 Office       ← 지금 사내 설정
```

---

## 설치

[Releases](../../releases) 에서 최신 `.dmg` 를 받아 열고 **“netauto 설치.pkg”** 를 더블클릭하세요.
안내를 따라 **계속 → 설치**, 관리자 비밀번호 한 번. 끝입니다.

터미널은 필요 없습니다. 제거도 메뉴바 아이콘 › **“netauto 제거…”** 로 합니다.

> **“확인되지 않은 개발자” 경고가 뜬다면**
> dmg를 다른 맥에서 받았을 때만 나타납니다.
> pkg를 **오른쪽 클릭 → 열기** 를 고르면 설치됩니다.
> (애플 개발자 인증서로 서명하지 않아서 나오는 경고입니다)

설치되는 것:

| | |
|---|---|
| 메뉴바 앱 | `/Applications/NetautoBar.app` — 상태 표시 + 조작 |
| 백그라운드 서비스 | 실제 전환 담당. 로그인 화면에서도 동작 |
| 설정 파일 | 다시 설치해도 내 규칙은 유지됩니다 |

## 다른 사람에게 줄 때

**`.dmg` 파일 하나만** 주면 됩니다. (AirDrop · 메신저 · 메일 아무거나)

그 안에 설치 프로그램과 한글 안내문이 같이 들어 있습니다:

```
netauto 2.5.0 (디스크 이미지)
├── netauto 설치.pkg      ← 더블클릭
└── 처음 읽어주세요.rtf     ← 서명 경고 대처법 + 첫 설정 안내
```

> `.pkg` 만 보내도 설치는 됩니다. `.dmg` 는 그 pkg 와 안내문을 담은 봉투입니다.
> 받는 사람은 서명 경고를 만나게 되므로 안내문이 같이 가는 게 좋습니다.

### 받는 사람이 알아야 할 것

| | |
|---|---|
| **요구 사항** | macOS 13 (Ventura) 이상 · 애플 실리콘과 인텔 맥 모두 지원 |
| **서명 경고** | 개발자 인증서가 없어 “확인되지 않은 개발자” 경고가 뜹니다.<br>macOS 14 이하 → pkg **오른쪽 클릭 → 열기**<br>macOS 15 이상 → 더블클릭해 경고를 받은 뒤 **시스템 설정 › 개인 정보 보호 및 보안 › “확인 없이 열기”** |
| **첫 설정** | 설치 직후 기본 규칙은 “그 외 모든 Wi-Fi → Automatic → IP 그대로”, 즉 **아무것도 바꾸지 않습니다.** 회사 설정이 들어있지 않으니 각자 규칙을 만들어야 합니다 |

### 받는 사람의 첫 설정 순서

이 앱은 macOS의 **네트워크 위치**를 바꿔주는 방식이라, 위치가 먼저 있어야 합니다.

1. **시스템 설정 › 네트워크** › 오른쪽 위 `⋯` › **위치** › **위치 편집…** 에서 위치 추가 (예: *사무실*)
2. 그 위치로 전환한 뒤 사무실 IP·프록시를 설정하고 `Automatic` 으로 복귀
3. 메뉴바 › **설정…** 에서 규칙 추가 — *Wi-Fi 이름 = OfficeWiFi, 프로필 = 사무실, IP = 고정*

## 쓰는 법

메뉴바 아이콘을 누르면 패널이 열립니다.

```
┌──────────────────────────────────────┐
│  ┌──┐                                │
│  │🏢│  Office                         │  ← 아이콘 + 프로필 이름
│  └──┘  자동 · 규칙과 일치             │     + 지금 상태
├──────────────────────────────────────┤
│  Wi-Fi    OfficeWiFi                    │  ← 열이 맞춰진 현재 상태
│  IP       192.168.10.50 · 수동        │
│  프록시    PAC proxy.pac              │
├──────────────────────────────────────┤
│  프로필                               │
│  🏢 Office                          ✓  │  ← 눌러서 바로 전환
│  🌐 Auto                              │
│  직접 고르면 이 Wi-Fi에 있는 동안 유지    │
├──────────────────────────────────────┤
│  IP 주소                              │
│  ↻ 자동 (DHCP)                        │
│  # 4층 내 자리   192.168.10.50     ✓  │
│  # 회의실       192.168.10.51        │
├──────────────────────────────────────┤
│  ✦ 규칙대로 지금 맞추기                 │
│  ⏸ 잠시 멈추기                        │
│  ⚡ 자동 전환                    (●━ ) │  ← 스위치
├──────────────────────────────────────┤
│  ⚙ 설정…                              │
│  🔍 로그 보기                          │
│  🌐 시스템 네트워크 설정                 │
│  netauto 2.5.0            제거…  종료  │
└──────────────────────────────────────┘
```

지금 적용된 항목에는 **체크**가 붙고, 마우스를 올린 줄이 밝아집니다.
규칙과 지금 상태가 다르면 `규칙` 줄이 주황색으로 추가됩니다.

### 아이콘 읽는 법

| | |
|---|---|
| 🏢 **Office** | 사내 프로필 적용 중 |
| 📶 **Auto** | 일반 프로필 (DHCP) |
| ✋ | 내가 직접 고른 프로필 유지 중 — 자동이 양보한 상태 |
| ⏸ | 잠시 멈춤 |
| 🚫 | 자동 전환 꺼짐 |
| ⚠️ | Wi-Fi 미연결 또는 설정 오류 |

### 내가 직접 바꿔도 됩니다

메뉴에서 프로필을 직접 고르면 **그 Wi-Fi에 있는 동안은 자동이 안 건드립니다.**
다른 Wi-Fi로 옮기면 다시 자동으로 돌아옵니다.
바로 자동으로 되돌리려면 **“규칙대로 지금 맞추기”**.

## 설정 창 (⌘,)

터미널이나 설정 파일을 만질 필요 없이 여기서 다 합니다.

### 1. Wi-Fi 규칙

어떤 Wi-Fi에서 어떤 프로필을 쓸지.

| Wi-Fi 이름 | 프로필 | IP | 고정할 주소 |
|---|---|---|---|
| `OfficeWiFi` | Office | 고정 IP | 사무실 기본 (192.168.10.50) |
| `home` | Automatic | 자동 (DHCP) | — |
| `*` | Automatic | 그대로 두기 | — |

- **Wi-Fi 이름** — 옆의 `▾` 를 누르면 저장된 Wi-Fi 목록에서 고를 수 있습니다
- **`*`** 는 “그 외 모든 Wi-Fi”. 맨 아래에 두면 기본값이 됩니다
- **IP** — 세 가지 중 고릅니다
  - **그대로 두기** — IP 설정을 건드리지 않습니다
  - **자동 (DHCP)** — 공유기에서 자동으로 받습니다
  - **고정 IP** — 아래 “자주 쓰는 IP”에 적어둔 주소 중에서 고릅니다
- **프로필** 목록은 시스템(`networksetup -listlocations`)에서 그대로 읽어옵니다.
  시스템 설정 › 네트워크에서 위치를 추가하면 여기 자동으로 나타납니다

### 2. 자주 쓰는 IP

여러 개 적어두면 **규칙의 “고정 IP”** 와 메뉴의 **“IP 바꾸기”** 에서 골라 쓸 수 있습니다.

| 이름 | IP 주소 |
|---|---|
| 4층 내 자리 | `192.168.10.50` |
| 회의실 | `192.168.10.51` |

자리를 옮겼거나 IP가 충돌할 때, 시스템 설정을 파고들지 않고 메뉴에서 두 번 클릭으로 바꿉니다.

### 3. 프로필 이름표

메뉴바에 짧게 띄울 이름. `Office` → **Office**, `Automatic` → **Auto**.

### 4. 옵션

- 메뉴바에 프로필 이름 표시 (끄면 아이콘만)
- 프로필이 바뀔 때 알림 표시
- 내가 직접 바꾼 프로필은 그 Wi-Fi에서 유지

## 알아두면 좋은 것

### “프로필”이 뭔가요

macOS의 **네트워크 위치(Network Location)** 입니다.
시스템 설정 › 네트워크 에서 만들 수 있고, 한 프로필 안에

- IP 방식 (DHCP / 고정 / DHCP+수동주소)
- DNS
- **프록시** (PAC 포함)
- Wi-Fi·유선 어댑터별 설정

이 **전부** 들어 있습니다. 그래서 프로필 하나만 바꾸면 유선·무선이 같이 맞춰집니다.

이 맥에는 이미 두 개가 있었습니다:

| | `Office` (사내) | `Automatic` (그 외) |
|---|---|---|
| Wi-Fi IP | 고정 `192.168.10.50` | DHCP |
| USB 이더넷 IP | 고정 `192.168.20.50` | DHCP |
| 프록시 | PAC `proxy.pac` | 없음 |

netauto가 하는 일은 **이 둘 중 맞는 걸 골라주는 것**입니다.
새 프로필이 필요하면 시스템 설정에서 만든 뒤, 설정 창의 규칙에서 고르면 됩니다.

### 비밀번호를 왜 한 번만 묻나요

네트워크 설정 변경은 관리자 권한이 필요합니다. 그래서 구조를 이렇게 나눴습니다:

```
메뉴바 앱  ──(요청 파일)──▶  백그라운드 데몬(관리자 권한)  ──▶  실제 변경
```

앱은 직접 바꾸지 않고 “이렇게 바꿔줘”라는 쪽지만 남깁니다.
데몬은 설치할 때 관리자 권한으로 한 번 등록되므로, 이후 앱에서는 비밀번호가 안 뜹니다.

### 언제 반응하나요

Wi-Fi가 바뀌면 **거의 즉시** (`/var/run/resolv.conf` 변화를 감지).
놓치는 경우를 대비해 30초마다도 확인합니다. 이미 맞으면 아무것도 하지 않습니다.

## 문제가 생기면

**메뉴 › 로그 보기** 를 먼저 보세요. 무슨 판단을 했는지 다 적혀 있습니다.

| 증상 | 확인 |
|---|---|
| 아이콘이 ⚠️ | Wi-Fi 미연결이거나 설정 파일 오류. 설정 창을 열어 규칙 확인 |
| 안 바뀜 | 메뉴 상단 **상태** 가 “수동 지정 유지 중”이면 → “규칙대로 지금 맞추기” |
| 안 바뀜 | **프로필** 이름이 시스템의 네트워크 위치와 다른지 확인 |
| 너무 자주 바뀜 | 규칙이 겹치는지 확인. 급하면 **잠시 멈추기** |

터미널에서 볼 수도 있습니다:

```bash
netauto status              # 현재 상태 + 규칙 + 저장된 IP
netauto test OfficeWiFi        # 그 Wi-Fi면 어떻게 될지 (변경 안 함)
netauto log 100             # 로그
sudo netauto apply --force  # 강제 적용
```

## 개발자용

### 구조

```
bin/netauto                       데몬 + CLI (bash, 의존성 없음)
bin/netauto-uninstall             제거 (앱이 관리자 권한으로 실행)
etc/netauto.json                  기본 설정
launchd/dev.devpaulie.netauto.plist   데몬 등록
app/NetautoBar/Core.swift         설정 읽기/쓰기 + 상태 모델
app/NetautoBar/UI.swift           메뉴 + 설정 창
installer/scripts/{pre,post}install  설치 시 서비스 등록
installer/resources/              마법사 화면 · dmg 안내문
build-app.sh                      Xcode 없이 .app 빌드
build-installer.sh                pkg + dmg 빌드
setup.sh                          개발용 직접 설치 (터미널)
```

### 빌드

```bash
./build-installer.sh    # dist/netauto-<버전>.pkg + .dmg
./build-app.sh          # 앱만
./setup.sh              # 패키징 없이 바로 설치 (개발용)
```

Xcode 없이 Command Line Tools 만으로 만듭니다 — `swiftc` 로 SwiftUI `MenuBarExtra` 를
arm64·x86_64 두 번 컴파일해 `lipo` 로 합쳐 **유니버설** `.app` 번들을 직접 조립하고,
`pkgbuild` + `productbuild` 로 설치 마법사를, `hdiutil` 로 dmg 를 만듭니다.
개발자 인증서가 없어 앱은 애드혹 서명(`codesign -s -`), pkg 는 미서명입니다.

주의할 점 두 가지가 코드에 반영되어 있습니다:

- `pkgbuild` 는 페이로드의 `.app` 을 기본적으로 **재배치 가능**으로 표시한다. 그러면 설치 시
  같은 번들 ID 의 기존 앱을 찾아 그 위치에 덮어써서 `/Applications` 에 아무것도 설치되지 않는다
  → `--component-plist` 로 `BundleIsRelocatable=false` 고정.
- `MenuBarExtra` 의 `.menu` 스타일은 SwiftUI 를 실제 `NSMenu` 로 변환하는데, 그 과정에서
  **`Text` 항목이 전부 비활성(회색)으로 그려지고, 공백 정렬이 가변폭 글꼴에서 어긋나고,
  SF Symbol 이 버려진다.** 그래서 패널은 `.window` 스타일(일반 SwiftUI 뷰 계층)로 만들고
  `Grid` 로 열을 맞춘다. 메뉴바 라벨만은 `NSStatusItem` 버튼이라 SwiftUI 뷰가 아니므로
  `NSImage` 로 아이콘+글자를 직접 합성해 넘긴다.

설정 파일은 `/usr/local/etc/netauto/config.json` 하나이고,
**Swift 앱과 bash 데몬이 이걸 공유**합니다.
bash 쪽은 `plutil`로 JSON을 읽어서 외부 의존성이 없습니다.

### 설치 경로와 권한

| 경로 | 권한 | 이유 |
|---|---|---|
| `/usr/local/libexec/netauto` | `root:wheel 755` | root로 도는 코드는 root만 수정 가능해야 함 |
| `/usr/local/etc/netauto/` | `root:admin 775` | 앱이 설정을 원자적으로 저장할 수 있게 |
| `/usr/local/var/netauto/queue/` | `root:admin 775` | 앱이 요청 파일을 떨어뜨릴 수 있게 |
| `/Applications/NetautoBar.app` | 사용자 | `/Applications`는 admin 그룹 쓰기 가능 |

admin 사용자는 시스템 설정에서 이미 네트워크를 바꿀 수 있으므로 권한 상승이 아닙니다.
설정 파일은 SSID→위치 *이름* 과 IP 문자열만 담고, 적용 전에 위치 존재 여부와 IP 형식을 검증하므로 임의 명령 실행 경로가 없습니다.

### 자기 트리거 루프

프로필을 바꾸면 `resolv.conf`가 갱신되고, 그게 바로 데몬의 트리거입니다.
그래서 **“이미 원하는 상태면 아무것도 쓰지 않고 즉시 종료”** 를 가장 앞에 둡니다.
IP도 같습니다 — 현재 IP가 목표와 같으면 쓰지 않습니다. 테스트로 못 박아 뒀습니다.
